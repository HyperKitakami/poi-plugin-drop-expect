## 1. 目标与非目标

### 目标

回答三个具体问题：

1. **这个点位刷这艘船，单次到达的掉落率是多少？**（数据要显示来源、样本量、时间窗口）
2. **要达到 X% 的期望，需要刷多少次？花多少油弹钢铝桶？**
3. **我现有的资源够不够；不够的话，最多能刷多少次、能到多少期望？换一个点位会不会更省？**

### 非目标（v1 明确不做）

- 不自动采集自己的出击记录（不用逐船差分、不写 `api_req_map/*` 处理）——这是 C 方案留给 v2 的接缝。
- 不统计实测到达率/掉落率（done by drop-counter）。
- 不记录出击历史、不做日志表。
- 不做掉落预言（不预测下一把）。
- 不做多语种、不做导出分享（可后续加）。

## 3. 核心交互流程

### 3.1 首次配置（从零到出结果）

```
侧栏打开 → 空状态提示「先添加一个点位」
  → 点「添加点位」→ 选海域 2-2 → 选格子 B → 评价 SAB
  → 消耗表单（可留空，留空则该行总消耗显示「—」）
  → 「添加目标舰」→ 搜索「村雨」→ 选中
  → 该行出现「掉落率：未设置 [抓取]」
  → 点抓取 → 200 且有样本 → 显示 1.191%（样本 186182，窗口 08-29~09-28）
  → 结果表出现该点的所需次数与总消耗
```

### 3.2 日常使用

```
设定目标概率 90%（默认）→ 看「所需次数 / 总消耗」
现有资源自动带入 → 看「剩余 / 缺口」
若缺口为负 → 看反算：「现有资源最多 62 次 → 成功率 85.3%，瓶颈：铝」
想省钱 → 再加一个点位（2-3 G）→ 同一艘船两行并列 → 按「油」排序
```

### 3.3 异常行为（必须有明确文案，不能静默）

| 情况 | 行为 |
|---|---|
| kcwiki 404（该图/难度未收录） | 「该海域或难度暂无数据」+ 保留手改入口；不写任何值 |
| kcwiki 200 但 `data:{}` | 「该点位没有样本（统计期内无人到达或未记录）」 |
| 网络失败 / 超时（8s） | 「网络请求失败」+ 提示可手填；已有值不变 |
| 返回里没有目标舰 | 「样本中未出现该舰」+ 显示总样本量，供判断是「太稀有」还是「没数据」 |
| 抓到 `(无)` 条目 | 永不写入舰船列表（它代表无掉落，仅用于校验 Σ） |
| 掉落率 0 或留空 | 该行所需次数显示「—」，不显示 Infinity |
| Σp > 1（手填错误） | 行内红字「该点位掉落率合计超过 100%，请检查」；口径「至少一艘」按 min(Σp,1) 计算 |
| 目标舰 > 12 艘且口径为「全部收集」 | 提示「目标过多，已退回近似估算」并使用乘积近似（见 §4.3） |
| 消耗全为 0 | 总消耗显示「—」并提示「请填写单次消耗」 |
| 存储文件损坏 | 退避为 `state.json.bak`，以空状态启动，控制台记录原因 |

## 4. 计算模型

### 4.1 符号

| 符号 | 含义 |
|---|---|
| `p_i` | 目标舰 i 在**单次到达该点位**时的掉落率（kcwiki `rate/100` 或手填） |
| `r` | 该点位的到达率（默认 1） |
| `q_i = r · p_i` | 单次**出击**获得舰 i 的概率 |
| `t` | 目标期望（50/80/90/99% 或自定义） |
| `c` | 单次出击消耗向量 `[补给油, 弹, 铝, 入渠油, 入渠钢, 桶]` |

前提：一次到达最多掉一艘（`api_get_ship` 是单对象），各舰在同一次内互斥；各次出击独立。

### 4.2 三种口径（全部精确，不用近似）

**① 单舰**
```
P(n) = 1 - (1 - q_i)^n
n(t) = ceil( ln(1-t) / ln(1-q_i) )
E[n] = 1 / q_i
```

**② 集合「至少一艘」**
因同次互斥，`q_any = Σ q_i` 是精确值：
```
P(n) = 1 - (1 - q_any)^n
n(t) = ceil( ln(1-t) / ln(1-q_any) )
```

**③ 集合「全部收集」**（旧实现用的是乘积近似，这里用精确 DP）
```
dp 初始 dp[∅] = 1
每步：dp'[m]        += dp[m] · (1 - q_any)      // 本次无掉落
      dp'[m | 1<<i] += dp[m] · q_i              // 本次掉 i
P_all(n) = dp[全集]
n(t) = 倍增找上界 + 二分（评估函数即上面的 DP）
```
旧实现的乘积近似 `∏(1-(1-q_i)^n)` 会**偏乐观**：p=[30%,30%]、n=5 时精确 0.6741 / 近似 0.6921（+1.8pp）；p=[3%,2%] 时仅差 0.25pp。DP 成本为 `O(n·2^k·k)`，k=2 时完全可忽略，故直接精确。

一次 DP 跑到 `n_max` 即可同时得到整条曲线（记录每步的 `dp[全集]`），供概率曲线复用，不必重复计算。

**退化与边界**

| 条件 | 处理 |
|---|---|
| `q_i = 0` | `n = Infinity`，UI 显示「—」 |
| `q_i = 1` | `n = 1` |
| `t ≥ 1` | `Infinity` |
| `r = 0` | 同 `q=0` |
| `Σq > 1` | 提示配置错误；「至少一艘」用 `min(Σq,1)` |
| `k > 12` | 退回乘积近似 + 提示 |

### 4.3 资源

```
need_j = n(t) · c_j
剩余_j  = have_j - need_j          （have 来自 poi，可手改）
够不够  = 所有 j: need_j ≤ have_j
```
反算：
```
n_max   = min_j floor(have_j / c_j)      // c_j = 0 的项跳过
瓶颈     = argmin_j floor(have_j / c_j)
成功率   = P(n_max)                       // 按当前口径
```

### 4.4 单次消耗的实测来源（借 WMFG 的历史记录）

C 方案不自己采集，但可以「借」现成的历史数据：

- 文件：`APPDATA_PATH/wheres-my-fuel-gone/{提督ID}/sortie_records.json`
- 一条记录 = 一次出击；逐船 `consumption` = `[补给油, 弹, 铝, 入渠油, 入渠钢, 喷式强袭钢]`
- 本插件按 `map.id` + 时间戳（可设时间段）筛选，对六项求均值；桶按「用掉几个」累加
- **记录只有海域、没有格子**：得到的是整个海域的均值。路线固定时够用，路线会变时误差留在样本里 → UI 必须连样本数与时间区间一起显示
- 支援 / 陆航单独统计但**不计入**（它们本身也是估算，混进来会污染"实测"这个前提），UI 单独提示
- 样本 < 10 时标注「样本较少」：实测 2-2 全部 410 次的补给油均值 38.8，最近 30 天只剩 4 次、均值 75.5
- 文件按 `mtime + size` 缓存解析结果，避免每次点击都重新 parse 十几 MB

读失败（未装 WMFG、文件不存在、正在被写入）只返回原因，不抛错——那是别人的插件写的数据。

### 5.2 持久化

- 路径：`APPDATA_PATH/plugin-data/poi-plugin-drop-expect/state.json`（poi 的插件数据约定，与其他插件一致）。早期版本曾写过 `APPDATA_PATH/drop-expect/`，新位置为空时会读一次旧文件并在启动时立即搬到新位置，旧文件保留不删。
- 白名单：`$dataVersion` / `targets` / `points` / `have` / `ui`。`ready` 不落盘。
- 写入：临时文件 + `rename`；变化后 500ms debounce；`pluginWillUnload` 立即 flush。
- 读取：`pluginDidLoad` 内**同步**读取并 dispatch，之后再挂 observer（避免「恢复覆盖用户操作」的竞态）。
- 坏文件：先 `rename` 为 `state.json.bak[.n]`，再以空状态启动。
- 迁移：`$dataVersion` 不匹配时走 `migrate(old)`；未知版本 → 退避 + 空状态，不阻塞启动。

```js
// calc/probability.es —— 全部返回 number，不可达返回 Infinity
singleP(q, n)

anyOfP(qs, n)          // qs: number[]
anyOfN(qs, t)
```

## 7. 技术选型与理由

| 选择 | 理由 |
|---|---|
| `.es` 入口，不打包 | poi 侧 Babel 转译，改完刷新即可（drop-counter 同款） |
| **零运行时依赖** | 旧实现 import 了未声明的 `lodash`/`reselect`/`path-extra`（缺陷 D9）。一切用原生数组/对象方法 |
| 纯函数 + 注入副作用 | 让 `calc/` 可以 `node --test` 直接跑，不需要 poi（drop-counter 的 109 个测试就是这么来的） |
| `@blueprintjs/core` 组件 | poi 自带；颜色走主题变量，天然适配深浅色（修复 D8/D12） |

## 10. 已知限制与待解决问题

### 已知限制

1. **掉落率语义是「每次到达」**，不是「每次出击」。有撤退时靠 `r` 修正；`r` 若估错，结果就错，UI 必须写明。
2. kcwiki 是 30 天滚动窗口且缓存可能滞后数周；活动图冷启动期样本极少，此时应优先手填。
3. 不区分敌舰编成（`enemy` 字段未用）。同一格不同编成掉落率不同时，聚合值会失真。
4. 支援/陆航费用需用户自行摊入「单次消耗」。
5. 「全部收集」的目标数上限 12，超过退回近似。
6. 入渠油/钢是**估价**（按入渠价折算），不是实际支出；不修船的实际成本更低。
7. 「最优点位」只按单列资源/次数比较，不做多资源加权（避免伪精度）。
